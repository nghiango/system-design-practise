# Flash Sale plan (2026-11-24)

- seckill-api: POST /api/items {name, stock, price} creates item in Postgres `items` and preloads Redis `flash-sale:stock:<id>`; GET /api/items returns id/name/stock (from Redis when available); POST /api/sales {itemId, orderId} runs a Lua script: if stock>0 decrement and return ok, else sold-out — atomic, one Redis round trip. On success publishes {"orderId","itemId"} to flash-sale.order.created and returns 202 {orderId}; else 409 sold out. Lua failure → 503 (fail closed, never oversell).
- order-worker: @KafkaListener group `${SD_KAFKA_GROUP_PREFIX}order-worker`; idempotent INSERT into `orders(order_id pk, item_id, status)` via ON CONFLICT DO NOTHING, then `UPDATE items SET stock=stock-1 WHERE id=? AND stock>0`. If the DB decrement fails (drift), compensate: INCR the Redis stock back and mark order failed — documents the saga-style compensation choice.
- Flyway in order-worker? NO — schema lives in seckill-api? Choose: seckill-api owns schema (items, orders) via Flyway; worker starts after? Argo creates both at once → race. Put Flyway in BOTH? Migrations are idempotent and flyway lock serializes them — safe to run in both, but cleaner: put schema in order-worker too is wrong owner. Use Flyway in seckill-api and let worker's consumer retry if table missing (Spring Kafka retries; add retryable listener errors config or just let it backoff). Simpler and safe: both run the same Flyway migration set (flyway_schema_history lock handles concurrency) — acceptable for practise, documented.
- Redis keys under `${SD_REDIS_KEY_PREFIX}` (flash-sale:). Lua script: `local s=tonumber(redis.call('GET',KEYS[1]) or '0'); if s>0 then redis.call('DECR',KEYS[1]); return 1 else return 0 end`.
- Tests: Lua path unit tests with mocked Redis (success/sold-out/drift), consumer idempotency + compensation unit tests; Testcontainers integration (Postgres+Redis+Kafka if feasible) proving 100 orders on stock=100 never oversells (concurrent unit test with 100 threads against real Redis is the key evidence).
- k6 load/links-style script `load/seckill.js`: seed item with stock=100, fire 500 concurrent buys, assert exactly 100 succeed → oversell evidence.
- Docs: README per template (capacity estimate, why Lua/Redis gate vs DB lock/optimistic/queue alternatives, failure modes), decisions/001-redis-lua-gate.md, 002-kafka-order-events.md. PROGRESS.md update.
